## 1. Release shape

v5.3 is a **fresh publish** (not an upgrade). Reason: Sui keeps every old
package version callable forever, so the v5.2 wager-expiry exploit can only be
fully retired by new objects that carry a version gate.

Everything ships in one publish:

| Module | Status |
|---|---|
| `character` | + `version` field on Character / CharacterRegistry |
| `item`, `equipment`, `marketplace`, `royalty_rule` | unchanged logic, + version gate where shared |
| `arena` (1v1 wagers) | v5.3 fixes (30-min expiry, challenger fight-lock) + version gate |
| `guild` | done on branch (44 tests) + version gate |
| `guild_war` | **new** — this spec §3 |
| `version` | **new** — `VERSION` const + `AdminCap`-gated `migrate()` per shared type |

### 1.1 Version gating (all shared objects)

- Every shared object gets `version: u64`.
- Every public mutating function asserts `obj.version == VERSION` (`EWrongVersion`).
- On a future upgrade: bump `VERSION`, call `migrate(&AdminCap, obj)` → old
  package code aborts on migrated objects. This is the Sui-recommended pattern.

### 1.2 Migration cost (testnet)

- Characters re-minted (players create again; no data carry-over).
- Item NFTs re-minted under the new `Item` type — new **medieval** catalog
  (§5.4) replaces the Ponke / Scavenger meme sets.
- New TransferPolicy + royalty rule, new TREASURY kiosk.

## 2. Combats.ru reference (what we copy)

- 5 zones: Head, Chest, Stomach, Belt, Legs. Pick attack zone(s) + block zone(s). *(already in engine)*
- Battle types: 1v1 duel, **group battle** (team vs team, organiser sets size / level rule / start delay), **chaotic** (auto-split teams), **clan battle**.
- Group battle: each fighter is paired with **one current opponent**; the exchange resolves when both have submitted; then each is re-paired with the next living enemy. Turn timeout → auto action.
- "Scales" (весы): sides are balanced before start.
- Battle screen: own paper-doll left, opponent paper-doll right, zone radio buttons centre, battle log below, roster of both teams with `[HP/maxHP]` and level.
- Character card everywhere: name, `[level]`, clan emblem, HP bar, stats (STR / DEX / INT / END), W/L/D.

## 3. Guild Wars (`guild_war.move` + server engine)

### 3.1 Flow

1. **Declare** — Leader/Officer of Guild A calls `declare_war(guild_a, guild_b_id, team_size, stake, level_rule, start_delay)`.
   - `team_size`: 2..10 per side.
   - `stake`: per-fighter SUI (0 allowed = honour war, no money).
   - `level_rule`: any / same / ±1 (vs the declaring officer's level).
   - `start_delay`: 5 / 10 / 15 / 30 min.
2. **Accept** — Leader/Officer of Guild B calls `accept_war`. Unaccepted declarations expire at start time.
3. **Sign up** — members of either guild call `join_war(war, character, stake)` until full or start time. Checks: guild member, level rule, not fight-locked, not in another war, exact stake.
4. **Start** — TREASURY `start_war` at/after start time:
   - **Scales**: both sides trimmed to `min(|A|, |B|)`; last signers refunded.
   - Fewer than 2 per side → war cancelled, everyone refunded.
   - Both guilds war-locked (`guild::set_war_lock`), fighters fight-locked.
5. **Fight** — off-chain server engine (§3.3).
6. **Settle** — TREASURY `settle_war(winner_side)`:
   - Pot = all stakes. 5% fee → TREASURY. 95% split equally among **all** winning-side fighters (dead or alive).
   - Draw → full refund, no fee.
   - Guild `wins/losses/draws` + guild rating (ELO) updated; war locks released.
7. **Escape hatch** — any participant can `reclaim_stalled_war` after 60 min in ACTIVE → full refunds (same design as `reclaim_stalled_wager`).

### 3.2 On-chain safety

- One open war per guild; one war per fighter.
- Stakes held in the `GuildWar` shared object; only the four terminal paths above move funds.
- Rounding dust from the equal split goes to TREASURY (never stuck).
- All state transitions emit events for the lobby indexer.

### 3.3 Server group-combat engine

- Reuses `resolveTurn` (zones / damage / crits / blocks) unchanged.
- **Pairing**: each living fighter has one current opponent. When a pair's exchange resolves, both are re-paired with the least-engaged living enemy. An unpaired fighter (odd count) waits for the next free enemy.
- **Timeout**: 20 s per exchange → auto random action (as 1v1).
- **End**: one side fully dead → winner. Hard cap 25 min → side with higher total HP% wins, equal → draw.
- Spectators: anyone can watch (existing spectator path).

## 5. Visual redesign — "dark medieval"

### 5.1 Mood

Grim, cold, evil. Iron, stone, ash, bone. No neon, no candy colours, no memes.
Think a torch-lit dungeon arena, woodcut / engraving illustrations.

### 5.2 Palette (grey / black / white)

| Token | Hex | Use |
|---|---|---|
| `--void` | `#070707` | Page background |
| `--stone-900` | `#111111` | Panels |
| `--stone-800` | `#1b1b1b` | Raised panels, inputs |
| `--iron-600` | `#3a3a3a` | Borders, dividers |
| `--iron-400` | `#6b6b6b` | Muted text, disabled |
| `--ash-200` | `#bdbdb7` | Body text |
| `--bone-50` | `#ece8df` | Headings, key numbers |
| `--blood` | `#7a0f0f` | **Only** HP loss / damage / death (D3 approved) |

Items have no rarity tiers (v5.3 decision) — only level and stats; see docs/ITEM_DESIGN_GUIDE.md.

### 5.3 Type

- Headings: blackletter (`UnifrakturCook`) or engraved caps (`Cinzel`) — Google Fonts.
- Body: `IM Fell English` / `EB Garamond`.
- Numbers (HP, SUI): tabular serif.

### 5.4 Screens (combats.ru layout)

- **Battle**: left paper-doll (13 slots around a silhouette) + HP bar + stats; centre zone picker (5 zones × attack / block) + timer; right opponent paper-doll; log below; group battles add both team rosters `Name [lvl] [HP/max]`.
- **Character**: paper-doll centre, stats + record left, inventory grid right.
- **Guild hall**: emblem, name, leader, member list with roles, treasury, war history, "Declare war" button.
- **Tavern / chat**: bottom-docked chat like combats.ru, room list right.
- **Items**: all medieval — swords, axes, maces, flails, spears, shields, helms, mail, plate. Engraving-style art.
